# GOOSE-Ex scripted bulldozer traversal

This is the first integration step for Issue #26. It loads a scene already
generated by the GOOSE-Ex converter, places the existing B10 bulldozer on its
SCM terrain, and drives a straight scripted route toward negative X. It records
the measured chassis position and orientation throughout the run.

## Run

Activate the project's `chrono` environment and run from the repository root.
First generate a scene with `python scripts/goose_to_heightmaps.py --headless`
or the direct converter, then use the `scene.json` it printed:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --headless \
  --output-dir outputs/goose_navigation
```

For a graphical run on WSL, software rendering can be used:

```bash
LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe \
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json
```

The default route starts at Chrono coordinates (0, 0), faces negative X,
travels at 0.6 m/s for 6 simulated seconds, and samples the trajectory every
0.1 s. For example, to choose another safe starting point and a shorter run:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --start-x 4 --start-y 1 --duration 4 --speed 0.5 \
  --headless
```

The command rejects a route whose bulldozer footprint would leave the terrain,
missing or mismatched scene data, and durations that are not whole multiples
of the configured simulation time step. It uses the scene's quality preset and
the grid spacing read by the existing GOOSE terrain loader.

## Outputs

The output directory, ignored by Git, contains:

| File | Contents |
| --- | --- |
| `trajectory.csv` | Time, measured chassis X/Y/Z position, yaw, and a reserved coarse semantic class column. |
| `run_manifest.json` | Source scene, starting pose, quality settings, actual duration, track speed, displacement, status, and output filenames. |
| `route_overlay.png` | Measured route, start and end positions over the initial GOOSE terrain height grid. |

A successful run requires the entire scripted duration to complete and at
least half of the commanded distance to be measured. An interrupted or
stationary run saves the available outputs, marks the manifest `incomplete`,
and returns exit status 2.

## Current limits

The GOOSE semantic maps and legend from Issue #22 have not yet landed. The
semantic column is therefore empty and the route image uses terrain heights,
not semantic colours. Once that output format is settled, the route can be
associated with coarse classes and overlaid on the label map.

This is a scripted straight traversal using the existing imposed-motion B10
drive. It does not perform path planning, react to obstacles, or offer manual
steering. The starting X/Y and height are configurable through the scene, but
the starting heading is fixed at zero. The blade is held raised; the goal is
vehicle/terrain integration and reusable trajectory output, not earthmoving.

## Tests

```bash
python -m unittest discover -s tests -p 'test_goose_navigation.py' -v
python -m unittest discover -s tests -p 'test_bulldozer.py' -v
```

The first suite checks coordinate orientation, route bounds, deterministic
sampling intervals, and exported CSV/PNG without PyChrono. The second needs
the `chrono` environment and checks the new positioned bulldozer start.
Run the command above against a real generated scene to verify the full
Chrono integration on the target machine.
