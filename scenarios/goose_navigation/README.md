# GOOSE-Ex vehicle traversal

This is the first integration step for Issue #26. It loads a scene already
generated by the GOOSE-Ex converter and places the existing B10 bulldozer on
its SCM terrain. Issue #37 adds the existing MathScavator9000 excavator through
the same runner. Select it with `--vehicle excavator`; the default remains
`--vehicle bulldozer`. Both use the terrain's caller-owned Chrono system with
their rigid demonstration floor disabled.

The bulldozer's default is a straight scripted route toward negative X;
the excavator drives toward positive X, with its boom and bucket raised.
Manual mode lets you drive and steer either vehicle yourself. Both modes record the
measured chassis position and orientation throughout the run.

## Run

Activate the project's `chrono` environment and run from the repository root.
First generate a scene with `python scripts/goose_to_heightmaps.py --headless`
or the direct converter, then use the `scene.json` it printed:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --headless \
  --output-dir outputs/goose_navigation
```

For a graphical run on WSL, software rendering can be used:

```bash
LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe \
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json
```

To drive the bulldozer yourself, use the same generated scene with manual
mode (do not add `--headless`):

```bash
LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe \
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --mode manual \
  --output-dir outputs/goose_navigation_manual
```

Click the simulation window to give it focus. Use W/S to drive, A/D to steer,
Space to stop, R/F to raise/lower the blade, T/G to tilt it, and X to reset
the blade. The controls also appear in the window. Close the window when done;
the measured route is saved at that point. Manual mode runs until you close
the window, or until an optional `--duration` limit (simulated seconds).
It requires the existing `pynput` dependency in `environment.yml`.

## Excavator

Run a repeatable excavator traversal on the same generated scene:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --vehicle excavator --mode scripted --headless \
  --start-x -4 --start-y 0 --duration 6 \
  --output-dir outputs/goose_navigation_excavator
```

To drive and articulate it yourself, omit `--headless` and select manual mode:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --vehicle excavator --mode manual --start-x -4 --start-y 0 \
  --output-dir outputs/goose_navigation_excavator_manual
```

Use W/S to drive, A/D to steer and Space to stop. Q/E swings the cab, R/F
raises/lowers the boom, T/G extends/retracts the arm, Y/H curls/uncurls the
bucket, and X resets articulation. In manual mode the selected vehicle's
controls appear on screen; scripted runs hide the panel so it does not cover
the vehicle. Each vehicle has its own starting view: the excavator's is set
back so the raised boom and bucket stay in frame. Graphical runs colour the
SCM mesh from the scene's coarse semantic map, matching `route_overlay.png`.
The camera remains free to rotate, pan and zoom using the existing mouse
controls; the runner does not reset it each frame.

For a reproducible screenshot, use scripted graphical mode with
`--capture outputs/goose_navigation_excavator/demo.png`. The final simulated
frame is saved before the command exits. `--capture` cannot be combined with
`--headless`, manual mode or the null renderer.

A saved 40-by-40-metre GOOSE-Ex export is available for testing without
downloading the source dataset:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene tests/fixtures/goose_label_viewer_real/scene.json \
  --vehicle excavator --start-x -4 --duration 2 \
  --capture outputs/goose_navigation_excavator/demo.png \
  --output-dir outputs/goose_navigation_excavator
```

The default bulldozer route starts at Chrono coordinates (0, 0), faces negative X,
travels at 0.6 m/s for 6 simulated seconds, and samples the trajectory every
0.1 s. For example, to choose another safe starting point and a shorter run:

```bash
python -m scenarios.goose_navigation.run_demo \
  --scene outputs/goose/<frame-name>/scene.json \
  --start-x 4 --start-y 1 --duration 4 --speed 0.5 \
  --headless
```

The command rejects a route whose selected vehicle footprint would leave the terrain,
missing or mismatched scene data, and durations that are not whole multiples
of the configured simulation time step. It uses the scene's quality preset and
the grid spacing read by the existing GOOSE terrain loader.
The legacy bulldozer clearance remains 1.8 m on each side. The excavator uses
2.0 m toward negative X, 5.5 m toward positive X and 1.7 m to either side of
the chassis, covering the tracks and raised traversal boom/bucket. A valid
bulldozer start may therefore be rejected for an excavator near the right edge.

## Outputs

The output directory, ignored by Git, contains:

| File | Contents |
| --- | --- |
| `trajectory.csv` | Time, measured chassis X/Y/Z position and yaw, and the coarse semantic class beneath each chassis position. Unlabelled or out-of-bounds positions say `unobserved`. |
| `run_manifest.json` | Selected vehicle name and `vehicle_key`; source scene and format version; semantic sources; starting pose, validated footprint, quality, duration, speed, displacement, SCM modified-node count, status, and output filenames. |
| `route_overlay.png` | Measured route, start and end positions and the vehicle's validated footprint at each end, over the scene's coarse semantic map, with a colour key. |

A successful scripted run requires the entire duration to complete and at
least half of the commanded distance to be measured. An interrupted or
stationary scripted run saves the available outputs, marks the manifest
`incomplete`, and returns exit status 2. A manual run records the time driven
and is complete when you close its window after simulation has begun.

## Current limits

Version 2 GOOSE scenes use the exported `semantic_coarse.npy` and
`semantic_legend.json` from the scene manifest. The nearest semantic grid cell
at each sampled chassis XY supplies the class name. This describes the map at
that point, not the soil material or a collision property. Version 1 scenes
remain usable: their semantic column is blank, and their route image shows
terrain height instead. For a version 2 scene, missing, misaligned, or invalid
semantic assets stop the run with an error.

Both vehicles use their existing imposed-motion drives and do not
perform path planning or react to obstacles. Manual mode reuses each vehicle's
existing keyboard controller; stay within the generated terrain bounds as you
drive. The starting X/Y and height are configurable through the scene, but the
starting heading is fixed at zero. Scripted mode holds the bulldozer blade or
excavator boom/bucket raised;
the goal is vehicle/terrain integration and reusable trajectory output, not
earthmoving. SCM contact/deformation is measured in integration tests, but
drive traction, suspension/height following, digging and autonomous navigation
are not modelled by this demonstration. Vehicle height follows the initial
terrain elevation only; the imposed drive holds it at that height along the
route. Manual swinging/articulation can extend beyond the validated starting
footprint. Another team member still needs to test the full excavator command
on a different machine before Issue #37 is considered complete.

## Tests

```bash
python -m unittest discover -s tests -p 'test_goose_navigation.py' -v
python -m unittest discover -s tests -p 'test_bulldozer.py' -v
python -m unittest discover -s tests -p 'test_excavator.py' -v
python -m unittest discover -s tests -p 'test_goose_navigation_integration.py' -v
```

The first suite checks coordinate orientation, route bounds, version 2 semantic
alignment and output, version 1 compatibility, deterministic sampling intervals,
and exported CSV/PNG without PyChrono. The second needs
the `chrono` environment and checks the new positioned bulldozer start.
Run the command above against a real generated scene to verify the full
Chrono integration on the target machine.
The integration suite uses the unchanged GOOSE converter to generate a small
synthetic soil scene, runs both real vehicle models on SCM, checks shared-system
ownership and non-zero deformation, compares repeated excavator exports, and
tests every excavator key through the existing controller. Both navigation
controllers also run through Irrlicht's null renderer in subprocess smoke tests.
For that smoke mode use `--mode manual --duration 0.2 --smoke-test`; it supplies
deterministic held keys without starting a desktop keyboard listener.
